## 0. 一页纸结论

1. **审计报告四条主结论全部成立**，且第 2 条（业务闭环）比报告写的更弱：**成本核算、审批引擎、平台订单集成三块是零实现**，不是"待验收"。
2. 本次复核**另发现 12 项报告未列或低估的缺口**，其中 5 项是**直接违反 v1.3 岗位"禁区"的职责分离缺陷**（收货人可自检自判、采购专员可自确认订单、会计可执行付款、出纳可开发票、仓管可自审自己的库存调整）。
3. 已确认的硬事实：`menu_items` 有 **7 个入口映射到带参路由而被 `NavigationService` 静默跳过**（审计只点了"我的任务"1 个）；`approval_flows` 表 **0 行**且 `ApprovalService::start` **没有任何调用方**；`integration_outbox` / `domain_events` / `sync_tasks` **全 0 行且无写入方**。
4. 当前数据库是**演示库**：`purchase_orders`、`goods_receipts`、`inspection_records`、`customer_invoices`、`payments`、`rnd_projects`、`ecom_orders`、`crm_leads` **全部 0 行**。所以"业务闭环"既无实现也无数据可验收——这一条不能靠补测试解决，必须补流程 + 造验收剧本。
5. 计划分四批共 **22 项整改**（P0 8 / P1 9 / P2 5），另 **6 项明确暂缓**：**P0 约 11 人日**先修权限与 SoD，**P1 约 35 人日**补业务闭环（按 D-14 标准成本、D-15 审批链、D-20~D-22 范围调整），**P2 约 7 人日**补治理。总计约 **53 人日**，不含真实数据准备。Q1~Q6 已拍板（§9）；D-20~D-22 为追加范围调整（§9.8）。
6. **不建议按现状扩充功能**：P0 未清之前新增页面/模块，会把 SoD 缺陷复制到新模块（v1.3 §8.3 已出现过"粗粒度权限既当列表守卫又当读取凭据"的同类问题）。

### 9.2 审批链矩阵（D-15 落地定义）

> 所有链条统一规则：**申请人 ≠ 审批人**（同人兼任两岗时写 `acting` 记录并禁止自批，落 `audit_logs`）；审批期间业务**不得先执行**；`ApprovalController::index` 只显示"待我审"。

| 业务动作 | 发起（权限） | 审批节点 | 通过后动作 | 驳回后 |
|---|---|---|---|---|
| 采购订单确认 | 采购专员 `purchase.create` | **采购主管（主审）+ 总经理（代批）**，1 级；代批记 `delegated=true` | 订单 → confirmed，可收货 | 回 draft，改单重提 |
| 采购订单关闭 | 采购专员 `purchase.create` | 采购主管（主审）+ 总经理（代批） | → closed，未收量清零需填原因 | 保持 confirmed |
| 盘点/库存差异调整（超阈值） | 仓管 `inventory.adjust.request` | 仓库主管（1 级，**新增 `inventory.adjust.approve`**） | 生成调整流水、库存变动 | 单据 void，库存不动 |
| 付款 | 会计制单 `finance.payment.manage` | 会计审核（非制单人）→ 总经理（2 级，**新增 `finance.payment.approve`**） | 出纳 `finance.payment.execute` 才可执行 | 退回制单 |
| 发票开具 | 会计制单 `finance.invoice.manage` | 会计审核（非制单人）→ 总经理（2 级，**新增 `finance.invoice.approve`**） | 开票并记账、AR 增加 | 退回，不记账 |
| 研发任务延期 | 任务执行人 | 研发经理（1 级，**新增 `rnd.extension.approve`**） | `end_date` 顺延、`is_overdue` 复位、写延期记录 | 保持原期 |
| 客户退货 | 销售专员 `sales.create` | 销售主管（1 级，**新增 `sales.return.approve`**） | **审批通过后**才 available→returned（改掉"先动库存"） | 不动库存 |
| 领料超耗 | 生产组长（已有独立审批） | 生产主管 `production.issue.approve` | 发料 | 不发料 |

> 注：采购订单"关闭"与"确认"共用 `purchase.confirm`。申请人若就是审批人（一人兼采购专员+主管），按"申请人≠审批人"直接拒绝，由**总经理代批**（D-21）：代批须填理由，记录标 `delegated=true`，并进月度代批占比统计（>30% 告警），防止代批变常态。总经理本人也不得自批自己发起的单据。
> **新增流合计 6 条**：`purchase_order.confirm`（关闭复用）、`stocktake.adjust`、`payment.execute`、`invoice.issue`、`rnd.extension`、`sales_return.approve`。**领料超耗沿用现有 `production.issue.approve`，不新增流**；**销售订单确认**已有独立权限 `sales.confirm`（专员无此权），保持"权限分离"不再叠审批，避免两层卡单。

### 9.3 库存调整阈值规则（D-16）

| 项 | 规则 |
|---|---|
| 调整金额口径 | 盘点差异数量的绝对值 × 物料标准成本；无标准成本时取"最近采购价"；两者皆无 → **强制审批** |
| 阈值 | `config/erp.php → inventory.adjust_approval_threshold = 500`（元，**含等于**，即 ≥500 需审批），可按财务要求调整 |
| 低于阈值 | 直接生效，但**仍生成 `inventory_adjustments` 单据**（`auto_approved=true`）+ `audit_logs`，并在日报汇总给仓库主管 |
| 高于阈值 | 走 §9.2 的"仓库主管单审"，未批不得动库存 |
| 不适用 | 跨仓调拨（`transfer`）不算调整，单独走调拨单；采购/销售引起的状态变化不走此阈值 |
| 阈值变更 | 仅总经理可改，改动写 `audit_logs` 并在本文档版本记录登记 |

### 9.4 标准成本模型（D-14）

| 项 | 定义 |
|---|---|
| 主表 | `material_standard_costs`：`material_id, version, standard_cost, currency, effective_from, effective_to, status(draft/active/superseded), approved_by, approved_at` |
| 版本规则 | 同一物料同一时点**仅 1 个 active**；改价 = 新建 version（走审批），**禁止覆盖历史**；旧单据按"发生时点的 active 版本"结转 |
| 销售成本结转 | `sales_order_lines.std_cost_amount = qty × 发货时点 active 标准成本`；出货时写 `inventory_transactions(std_cost, qty)` |
| 采购价差 | `price_variance = (实际采购单价 − 标准成本) × 数量`，入 `inventory_transactions`，**不进单笔销售成本**，报表单列 |
| 毛利口径 | `毛利（标准成本）= 开票净额 − 标准成本结转`；报表同时展示"价差"作为期间差异，**不摊入单笔毛利**（避免同一笔毛利两套算法） |
| 期初（D-20） | **演示环境**：`DemoSeeder` 为 A 类物料写虚拟标准价（`source=demo`，页面标"演示数据"）；**上线后**：客户财务在"标准成本维护"页按实际 BOM/采购价重定价，系统不预置任何真实价 |
| 维护入口（D-20） | 权限 `cost.standard.view/manage`，仅财务/总经理可见；页面=版本列表 + 新建版本 + 停用 + 变更审批 + 影响预览（"哪些在途订单会受影响"）；业务角色访问 403 |
| 发货闸门 | 有 active 标准的物料按标准结转；无标准的先按"最近采购价"临时生成 `source=fallback` 版本并**标黄提示**，不阻断演示；`config/erp.php` 提供 `cost.block_ship_without_standard`（默认 false，上线后由客户决定是否硬性阻断） |
| 差异分析 | 新增报表：价差（按供应商/物料/月）、量差（标准用量 vs 实际领料） |

### 9.8 追加范围调整（D-20 ~ D-22，2026-11-09）

**9.8.1 标准成本：演示虚拟价 + 客户财务维护（D-20）**

- 演示阶段不为"真实定价"卡流程：`DemoSeeder` 直接给 A 类物料写虚拟标准价（`source=demo`），所有报表页脚注明"演示价，上线前由财务替换"。
- 上线后价格由**客户财务**在"标准成本维护"页维护（新增/停用版本、变更审批、影响预览），我方不预置真实价、不代客户定价。
- 因此 P1-02 的验收改为：**演示价能跑通结转与价差 + 财务能自助改版本 + 业务角色看不到该页**，不再要求"上线前完成全物料定标"。

**9.8.2 采购确认：主管主审 + 总经理代批（D-21）**

- 审批节点：采购主管（主审）→ 通过即生效；总经理可**代批**，但代批须填理由、记录 `delegated=true`。
- 硬规则不变：申请人 ≠ 审批人（含代批人）；总经理不得自批自己发起的单据。
- 治理：`erp:approval:audit` 按月统计代批占比，>30% 告警——代批是兜底，不是常态通道。

**9.8.3 电商接入：只做引导、设置与适配器（D-22）**

- **本期交付**：平台清单（国内外）→ 接入向导（三步）→ 平台设置页（启停/默认仓/到期提醒）→ 手动添加任意平台 → 适配器接口与各平台骨架 + 契约测试。
- **本期不做**（避免"接完发现跑不通"）：真实订单拉取落库、订单转销售单、发货回写、outbox 重试/死信、对账。这些统一进 P3-8。
- **产品口径要写清**：接入页需明确"当前版本已完成平台配置接入，交易同步将在后续版本开放"，避免客户以为接完就能自动同步订单。
- 对客户的价值是"自助接入 + 后续可扩展"，不是"本期已打通交易"——这一点必须在说明书与销售话术里一致。
