# P3-02 执行记录：APS 产能排程与有限产能（2026-11-10）

> 对应计划：`docs/整改完善计划-v1.4.md` §4.4 第 2 项"APS 产能排程与有限产能（先做 MRP 净需求）"。
> 结论：**已完成**。MRP 净需求在 P1-08 已交付，本轮在其下游做**有限产能正排**：按工作中心日产能把未完工工单的工序逐日占用，生成可查的日负荷看板，任何工作中心任何一天都不超日产能。

## 1 与"无限产能"的差别

| 维度 | 常见无限产能 | 本轮有限产能 |
|---|---|---|
| 排程依据 | 只按工单交期推算日期 | 工单交期 + 每道工序的工作中心日产能 |
| 产能约束 | 不看 | **每天每工作中心占用量 ≤ `capacity_per_day`** |
| 跨天 | 工序随意跨天 | 工序按剩余产能切分到多天，容量满即顺延 |
| 溢出 | 无感知 | 超出排程区间的继续排，但标记"溢出工单"数 |
| 结果 | 只给日期 | 落 `aps_plan_entries` 日负荷，可核对每天占用 |

## 2 数据表（迁移 `2026_11_10_000014_create_aps_tables.php`）

| 表 | 关键列 | 说明 |
|---|---|---|
| `aps_plans` | `plan_no` 唯一、`horizon_start/end`、`status`、`summary_json`、`created_by` | 一次排程一个方案；`summary_json` 存工单数/工序数/总工时/溢出数/各中心利用率 |
| `aps_plan_entries` | `plan_id`、`production_order_id`、`operation_seq`、`operation_name`、`work_center_id`、`work_date`、`hours` | **一工单一道工序一天一行**；日负荷 = 同中心同日 `hours` 求和 |

索引：`(plan_id, work_center_id, work_date)` 用于负荷看板，`(plan_id, production_order_id)` 用于工单窗口。

## 3 排程算法（`App\Services\ApsSchedulingService::generate`）

1. 取数：`production_orders` 中状态 `planned/released/in_progress`、`routing_id` 非空、`plan_qty > completed_qty`，按 `end_date`、`id` 升序（交期早的先排）。
2. 每张工单按 `routing.operations.operation_seq` 顺序排；工序可开工日 = `max(排程开始, 工单 start_date, 上道工序完成日)`。
3. 工序总工时 = `剩余数量 × standard_hours`；按天占用工作中心剩余产能，占用多少记多少，占满顺延次日。
4. 每天每中心初始产能 = `capacity_per_day`（空值按 8）；扣减到 0 后当天不再接活。
5. 超出 `horizon_end` 仍继续排（不截断），只把工单计入 `summary_json.overflow_orders`。
6. 方案编号 `APS-YYYYMMDD-###`（当天递增）；整段在数据库事务内，失败回滚不产生半成品方案。

**口径假设**（页面同步展示，避免误读）：
- `work_centers.capacity_per_day` 按"可用工时/天"使用（不是件数/天）；
- `routing_operations.standard_hours` 按"单件工时"使用（空按 1 小时/件）。

## 8 边界 / 未做

- **方案只是建议，不回写工单**：不修改 `production_orders.start_date/end_date/status`，避免排程把已发布工单的日期悄悄改掉。要"发布"需另做审批/回写。
- **无工作日历**：不识别周末、节假日、班次、停机；每天固定按 `capacity_per_day` 满额。
- **无换型/准备时间**：同一工作中心切换不同产品不扣 setup time。
- **无替代工作中心**：一道工序只排一个 `work_center_id`，不能自动转产线。
- **不看物料齐套**：不校验库存/采购到货，可能排出"料没到"的工单；MRP 建议与齐套检查是另外的动作。
- **计划状态只有 draft**：页面固定显示最新方案；没有发布/冻结/版本对比。
- **溢出明细不在日负荷矩阵**：矩阵只画 `horizon_end` 前，超出区间的行只在工单窗口与汇总"溢出工单"里体现。
- **单件工时口径**：若客户实际把 `standard_hours` 当作"整批工时"，排出的占用会偏大；上线前需按工厂口径校准该列语义。
