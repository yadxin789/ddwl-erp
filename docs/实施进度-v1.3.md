## 五、已知问题（非本轮引入）

1. `tests/Feature/ExampleTest` 断言 `GET /` 为 200，实际 302（未登录跳登录页）。
2. PHP 启动有 `curl` 模块 API 不匹配告警（XAMPP 环境），不影响命令执行。
3. `file.resource.view` 权限已不再被菜单引用（资料文件页改 `__auth__` 全员可见、上传单收 `file.resource.manage`），保留在权限库中未删。
4. 原 `finance.payments` 路由与"收付款执行"页面同 URI，已去重：GET 统一为 `finance.payment.execute`，POST 名保留 `finance.payments.store`（`finance/payments` 视图引用该名）。
5. S5 的一个口径取舍：`InspectionRecord` 没有 `department_id`，`department` 范围退化为"本人检验记录"；若 IQC/IPQC/FQC 要按环节看全量，应改为按 `stage` 过滤而不是加部门列。
6. 本轮验收暴露的系统性问题：旧权限是"粗粒度业务域权限"（`sales.view`/`purchase.view`/`production.view`），既当**列表页守卫**又当**数据读取凭据**，导致"给 A 看数据"必然"顺手开放列表页"。已按页拆出 `production.order.view` 等，但同类问题会在后续新增页面时复现，建议新页一律用"页面级权限"。
