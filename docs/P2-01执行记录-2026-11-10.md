## 2 本地 CI 门禁 `scripts/ci-gate.ps1`

调用：

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\ci-gate.ps1            # 全量：语法 + 路由 + 守卫 + 测试
pwsh -ExecutionPolicy Bypass -File .\scripts\ci-gate.ps1 -SkipTests  # 快速：只跑前三级
```

执行顺序与失败策略（任一步失败立即 `exit 1`）：

| 级 | 检查 | 说明 |
|---|---|---|
| 1 | PHP 语法 | 遍历 `app/routes/database/tests/bootstrap/config` 共 **378 个文件**，逐文件 `php -l`；任何一个 Parse error 即红 |
| 2 | 路由注册 | `artisan route:list --json`；非 0 退出即红。**额外自建"命名路由不重复"检查**：`route:list` 本身对重名不报错（实测 exit 0），门禁按 name 分组，重复即红 |
| 3 | 岗位/菜单/权限守卫 | `artisan erp:guard:check`；非 0 即红。**且把"缺口页"升级为失败**：输出含"以下菜单指向尚未建成的页面"即红——`guard` 自身对缺口页 exit 0、侧边栏自动跳过，这正是 CI 必须补的一刀 |
| 4 | 全量回归 | `artisan test`；非 0 即红 |

当前绿：`route:list` **265 条路由 / 命名路由无重复**；guard `岗位/兼容角色 33、共享菜单 11、名称映射 122、权限库 149、M1~M7 全部通过`；`artisan test` **100 passed / 2244 assertions**。

## 4 GitHub Actions 模板 `.github/workflows/ci.yml`

无远端仓库时先在本地跑 `scripts/ci-gate.ps1`；推到 GitHub 后流水线自动生效：

1. `composer install` → 复制 `.env` 并写 MySQL 连接（service 容器 `mysql:8.0`，库 `ddwl_erp_ci`）；
2. `php -l` 全量语法；
3. `route:list --json`；
4. `erp:guard:check`；
5. `migrate:fresh --force` + `db:seed --force`（测试依赖演示账号与种子数据，不是 RefreshDatabase）；
6. `artisan test` 全量；
7. `artisan test --filter=SoDTest` 单独再跑一次（SoD 回归单列，便于红灯定位）。

> 流水线未加缓存与并行分片，首次跑约数分钟；`vendor` 与 `.env` 不入库。

## 5 未做 / 边界

- **没有远端仓库**：只做了本地 `git init` + 基线提交，没有 `git remote`、没有推送；Actions 模板要等客户给仓库地址后才真正执行。
- **没有 pre-commit hook**：门禁是"手动/流水线调用"，未装 `.git/hooks/pre-commit`（装了会让每次本地提交都跑 40 秒语法 + 全量测试，暂不强制）。
- **测试依赖真实 MySQL 与演示种子**：CI 用 `migrate:fresh --seed` 重建；本地脚本直接跑现有开发库，**会写入少量测试数据**（多数用例用事务回滚，但 `SoDTest`/`PositionMatrixTest` 的 GET 与空表单 POST 不写业务数据；`acceptance-smoke` 不在门禁内）。
- **语法检查用 `php -l` 逐文件串行**（378 文件约 40 秒）；没有上 PHPStan/Pint，静态分析与代码风格不在本期门禁。
- **`.env` 不入库**，CI 的数据库账号密码写在 workflow 里（仅测试库，非生产凭据）。
- 门禁没有检查"文档与权限库一致性"（那是 `erp:guard:check` 的 M1~M7 范围）。
