## 0. 一页纸结论

| 问题 | 现状 | 本方案 |
|---|---|---|
| 岗位职责 | 22 个岗位只是组织架构表里的一行，没有职责定义 | 29 个岗位，每个都有"主责 / 禁区 / 上下游 / 产出 / 工作台卡片"，**禁区即守卫依据** |

## 1. 现状诊断（问题与证据）

### 1.1 菜单层：一份菜单给所有人

- 全站唯一侧边栏 `resources/views/layouts/admin.blade.php:20-232`，**54 项、15 个 nav-section**，另有 2 项无分组（安全审计、个人资料）。
- 只有 **10 处 `@can`**，覆盖约 22 项；**32 项完全无权限判断**（`:72-218`，CRM 3 / 质量 3 / 协同 8 / 财务 3 / 电商 9 / HR 3 / 审计与个人资料 2）。
- `:220-231` 用单个 `system.user.view` 包住"部署运维 + 用户管理 + 角色权限"三项，粒度错配。

### 1.2 角色层：管理员全量、岗位无角色

- `RoleSeeder.php:20-24` 给 `system_admin` 授予 `Permission::pluck('name')->all()`，实测 **104/104**，可做业务。
- `positions` 表（`2026_11_04_040000_create_departments_and_positions_table.php:32-44`）只有 `pos_code / pos_name / department_id / description / status`，**无角色绑定字段**。
- `DemoUserSeeder.php:31-35` 的 4 个岗位级账号无角色：登录后菜单照样显示，点开全 403。

### 1.3 路由与权限层：缺失、空转、后门

| 问题 | 证据 |
|---|---|
| 两条权限被引用但不存在（点击即 500） | `sales.confirm`（`web.php:134`）、`production.report`（`web.php:182-185`） |
| 33 条权限定义了却无任何路由校验 | `PermissionSeeder` vs `routes/web.php` |
| 盘点路由挂在生产模块权限下 | `production.stocktakes*`（`web.php:170-171,186-187`）挂 `production.view`，仓储岗进不去 |
| 跨岗位后门 | 仓管发货必须进"销售订单详情"；IQC 检验必须进"采购收货详情" |
| 按钮无守卫 | `sales/order-show.blade.php:71,78`（确认、出货）、`production/order-show.blade.php:43,70,85`（领料、报工、完工） |
| 无 403 页 | `resources/views/errors/` 不存在，越权返回 Laravel 默认灰页且无留痕 |
| 工作台无岗位裁剪 | `HomeController.php:21-32` 一次算 10 个指标（含应收应付）给所有人看 |

**结论**：菜单混乱不是样式问题，是"岗位—角色—菜单—页面—权限"五层没有一条链路打通。v1.2 把这条链路显式写出来，并让它可被脚本校验。

## 2. 目标模型与七条铁律

### 2.1 五层链路

```
岗位（positions，29 个） → 角色（roles，29 + 4 兼容） → 菜单名称数组（11 共享 + 业务项）
      → 页面（P-01~P-147，每页唯一主责岗位） → 权限（spatie，动作级） → 四层守卫
```

### 2.2 七条铁律

| # | 铁律 | 落地方式 |
|---|---|---|
| 1 | **管理员只管系统运维与后台管理，不参与业务** | `role_sys_admin` 不含任何业务权限；访问业务路由 → 403 + 审计 |
| 2 | **每岗位至少绑定 1 个角色** | `roles` 数组非空，M1 校验；4 个无角色账号补齐后方可上线 |
| 3 | **每岗位只能进自己的页面** | 页面唯一主责 + 共享页登记表（≤3 共享岗位）；其余 403 |
| 4 | **菜单即岗位投影** | 菜单名称数组 + 名称→路由→权限映射，无映射不渲染 |
| 5 | **通用项每岗都有** | 11 项共享菜单写进每个数组，`array_diff` 强制校验 |
| 6 | **按钮与路由同名同义** | 按钮 `@can` 权限 == 路由 `permission:`，禁止"按钮能点、路由不校验" |
| 7 | **失败即拒绝** | 配置缺失 → 空菜单；权限缺失 → 403；不提供"默认放行" |

### 2.3 岗位命名口径（回应第 3 条决策）

研发岗**保留前缀、绝不合并**：硬件工程师 / 软件工程师 / 结构工程师 / 包装设计师 / 外观设计师。理由是五类岗位的建码品类、BOM 结构、图档格式、审核要点都不同；合并会造成"谁都能改别人的 BOM"。菜单可以高度相似，但**权限与数据范围必须分开**。

### 3.1 相对现状的净变化

- **新增部门 2 个**：财务部（D-FIN，从行政部独立）、总经理室（D-GM）；电商部维持"建议新增"。

### 3.2 角色绑定要求（硬性）

1. 29 个岗位，每个 `roles` 数组 ≥1 个角色，**禁止空数组**（M1 校验）；
2. 现状 4 个无角色账号（`prod-supervisor`、`iqc-inspector`、`rnd-manager`、`admin-assistant`）必须在 S1 补齐，补齐前不得上线；
3. 一人多岗：`roles` 追加，不建"混合角色"；菜单取并集、**页面逐条校验**，审计记录实际岗位；
4. 岗位停用（`positions.status=0`）：角色保留，登录后仅可访问个人资料，其余 403。

## 4. 岗位职责详解（29 岗）

> 每条含：一句话职责 / 主责（做） / 禁区（不做） / 上下游 / 产出与考核 / 工作台卡片。
> **禁区是守卫设计的直接依据**——每条禁区都应能在 §6 找到"对应页面不存在或权限为空"的落点。

### 4.1 系统管理员 `SYS-ADMIN` · `role_sys_admin`

- **一句话**：保证系统能登录、能跑、能追溯，**不参与任何业务决策**。
- **主责**：用户管理（账号开停、重置密码、绑定岗位）；部门管理（部门编码/名称/启停）；岗位管理（岗位 CRUD 与角色绑定）；角色管理（角色 CRUD）；权限管理（权限字典 CRUD、角色授权）；AI 开通引导与设置（服务商、密钥、模型开关）；企业微信设置（应用配置、通讯录同步）；系统运维、同步任务、接口日志、状态映射、事件队列、多租户、安全审计。
- **禁区**：不得查看或修改任何业务单据（订单、BOM、库存、发票、薪资、工单）；不得代审批；不得改业务主数据（物料、客户、供应商）；**不得拥有任何业务权限**；不得进老板驾驶舱（那是经营视图，不是运维视图）。
- **上下游**：行政经理提交的组织与编制变更；**下游**：全系统用户。
- **产出**：账号开通时效、系统可用性、审计覆盖率、越权事件 = 0。
- **工作台**：待开通账号 / 今日登录失败 / 越权拦截数 / 同步任务失败 / 待处理审计告警。

### 4.2 生产主管 `D-PROD-P01` · `role_prod_manager`

- **一句话**：把销售订单变成可执行的工单，对交期、数量、工时负责。
- **主责**：订单转工单（按 BOM 展开需求）；工单下达与排产；齐套检查与领料推进；完工入库确认；参与在制/成品盘点清点；工作中心维护；工艺参数与工程共管；产能与交期回复。
- **禁区**：不得改 BOM 结构与工艺参数（工程岗）；不得改销售价格与账期；不得直接改库存数量（只能走盘点/调整流程）；**不得审批盘点差异**（仓库主管）；不得审批付款；不得看薪资。
- **上游**：销售订单、BOM；**下游**：生产组长、仓储（领料/完工入库）、IPQC、采购（缺料申请）。
- **产出**：工单准交率、齐套率、工时达成、在制周转。
- **工作台**：进行中工单 / 超期工单 / 待领料 / 待完工入库 / 今日报工汇总 / 异常工单。

### 4.3 生产组长 `D-PROD-P02` · `role_prod_leader`

- **一句话**：把工单拆到工序和人，报出真实的良品与不良。
- **主责**：接收并分解本线工单；派工；工序报工（良品/不良/不良代码/工时）；**领料申请**（G9）与进度跟踪；缺料上报；现场异常上报；盘点录入。
- **领料申请口径（D-13）**：**不设金额上限**，一律按**数量**申请（物料 + 数量 + 工单号 + 用途）；超出该工单 BOM 标准用量的部分需生产主管审批，超出部分单独标注"超耗"及原因；仓储按审批通过的数量发料，不校验金额。
- **禁区**：不得新建/下达工单（主管）；不得改 BOM；不得审盘点差异；不得看他人薪资与财务；不得改单价金额。
- **上游**：生产主管；**下游**：作业员、仓储（发料）、IPQC、工程（异常）。
- **产出**：日报工准确率、不良率、工时利用率、异常闭环时长。
- **工作台**：本线在制工单 / 今日待报工 / 缺料工单 / 今日不良 Top3 / 待处理异常。

### 4.4 作业员 `D-PROD-P03` · `role_prod_operator`

- **一句话**：按工单和 SOP 作业，如实报工。
- **主责**：查看本人工序工单与作业指导；提交报工；查看本人报工记录；查看本工序 SOP。
- **禁区**：不得建单、领料、改数量；不得查看其他工位工单与他人工时；不得进入任何管理页面。
- **上游**：生产组长；**下游**：组长（报工汇总）。
- **产出**：报工及时率、自检合格率。
- **工作台**：我的待做工序 / 今日已报工 / 良品不良统计 / SOP 快捷入口。

### 4.5 品质主管 `D-QC-P01` · `role_qc_manager`

- **一句话**：定义"什么叫合格"，并对不合格的处置负责。
- **主责**：检验模板与判定标准维护；缺陷代码字典维护；检验记录审核与判定；来料/制程/成品三段汇总；不合格处置（让步/返工/报废建议）；**供应商绩效评价**（G7）；质量报表。
- **禁区**：不得改 BOM 与工艺；不得直接放行库存（放行由仓储按判定执行）；不得审批付款；不得改销售订单。
- **上游**：工程（标准/图纸）、采购（来料）；**下游**：IQC/IPQC/FQC、仓储、生产（返工）、采购（扣分）。
- **产出**：来料合格率、制程不良率、客诉率、检验覆盖率、处置闭环率。
- **工作台**：待检批次（按阶段）/ 今日判定数 / 不合格待处置 / 供应商合格率 / 客诉待分析。

### 4.6 / 4.7 / 4.8 IQC / IPQC / FQC 检验员 `D-QC-P02/P03/P04`

- **一句话**：在自己负责的那一段，按模板判定，如实记录。
- **主责**：IQC 来料抽检与判定（触发合格入库或隔离）；IPQC 本线首件与巡检、异常即时上报；FQC/OQC 成品与出货前抽检、判定可否放行。
- **禁区**：不得改检验模板与判定标准（主管）；不得改数量、价格、库存；不得跳过抽检直接判定；**只能录入本人阶段**（阶段在页面锁定，不可切换）。
- **上游**：收货员 / 生产组长 / 仓管；**下游**：品质主管（复核）、仓储（按判定入库/隔离）、生产（返工）。
- **产出**：检验记录完整率、误判率、异常上报时效。
- **工作台**：我的待检任务 / 今日已检 / 不合格 Top 缺陷 / 待复核判定。

- **上游**：生产/仓储/电商的采购申请；**下游**：采购专员、供应商、仓储、品质、财务。
- **产出**：采购准交率、价格达成率、供应商合格率、呆滞金额。
- **工作台**：待审批申请 / 超期未到货 / 价格异常 / 供应商合格率 / 本月采购额。

- **主责**：组织架构（汇报线/负责人/编制）；**岗位编制维护**（G5）；员工花名册审核；请假与考勤规则；绩效组织与校准；公告与制度发布；会议室/语音室管理。
- **禁区**：不得查看薪资明细（财务部）；不得改业务单据；不得改账号与角色（运维）。
- **上游**：总经理/管理层；**下游**：人事专员、全员。
- **产出**：编制准确率、考勤合规率、绩效按期完成率。
- **工作台**：在编人数 / 本月入离职 / 待审请假 / 绩效待提交部门 / 今日会议。

### 4.24 人事专员 `D-ADM-P02` · `role_hr_specialist`

- **一句话**：把人的入转调离和考勤记准。
- **主责**：员工档案与入转调离；请假登记与统计；招聘与面试安排；绩效数据录入；组织架构只读。
- **禁区**：不得查看/录入薪资（财务部）；不得审批请假（主管/行政经理）；不得改业务单据；不得开账号。
- **产出**：档案完整率、考勤差错率、招聘到岗周期。
- **工作台**：待办入职 / 待录请假 / 在招职位 / 试用期到期提醒。

### 4.25 会计 `D-FIN-P01` · `role_fin_accountant`

- **一句话**：把应收应付记准、把账对平。
- **主责**：客户发票开具与核销；供应商账单登记与三单匹配；收付款**记账与核销**（执行归出纳）；对账（客户/供应商/库存）；资金流水台账；薪资核算；财务报表。
- **禁区**：**不得经手现金与银行支付动作**（出纳）；不得改销售/采购单据金额（只能挂账与差异反馈）；不得改库存；不得审批自己的付款；不得改 BOM 与工单。
- **上游**：销售（发货/开票申请）、采购（到货/对账）、仓储（库存）；**下游**：出纳（执行付款）、总经理（报表）。
- **产出**：账期准确率、对账差异率、月结时效。
- **工作台**：待开票 / 待收款 / 待付款审批 / 对账差异 / 本月应收应付余额。

### 4.26 出纳 `D-FIN-P02` · `role_fin_cashier`

- **一句话**：钱和票只经我手，账由会计记。
- **主责**：**收付款执行**（按已审批单据付款/收款，**含报销付款执行**）；**备用金管理**（借出/报销冲抵/余额盘点，台账与现金日记账联动）；**现金日记账**；**银行对账**（银行流水导入与勾对）；票据管理（支票/承兑/收据）；资金流水查看；应收应付查询（只读）。
- **备用金与报销口径（D-11，已拍板）**：**出纳兼管备用金与报销付款**——① 员工借款：出纳按已审批借款单支付并登记备用金台账；② 报销：业务主管/行政审批后，出纳在 P-142 执行付款，冲抵借款余额；③ 备用金月末盘点由出纳自查、会计复核（会计只看账不碰现金）；④ 备用金单笔与月度上限由财务制度设定（系统只记额度字段，不阻断审批）。
- **禁区**：**不得改账、不得开发票、不得做薪资核算**（会计）；不得改业务单据金额；**不得审批自己的付款/报销**（审批在业务主管 → 会计 → 总经理链路）；不得盘自己的备用金现金余额（由会计复核）；不得动库存。
- **上游**：会计（已审批付款单）、客户/供应商；**下游**：会计（回单交账）、总经理（资金日报）。
- **产出**：付款准确率、日清日结及时率、银行对账差异率、票据完整率、备用金余额准确率。
- **工作台**：今日待付 / 今日待收 / 现金余额 / 银行未达账项 / 票据到期提醒。

### 4.27 电商运营 `D-ECM-P01` · `role_ecom_operator`

- **禁区**：不得改库存实物、不得开票、不得改财务账、不得进生产工单与 BOM、不得改系统集成配置。
- **上游**：平台订单；**下游**：仓储（发货）、采购（备货）、客服（售后）、运维（同步异常）。

- **工作台**：今日订单 / 待发货 / 缺货 SKU / 进行中活动 / 同步失败。

- **禁区**：不得改价、不得改库存、不得发货、不得开票、不得进采购与生产页面。

### 4.29 总经理（老板）`D-GM-P01` · `role_gm`

- **一句话**：只看全局汇总，不做任何操作。

- **主责**：查看经营驾驶舱（营收/毛利/订单/库存/回款/质量/项目进度汇总）；查看报表中心（销售/采购/库存/质量/财务五张）。
- **禁区**：**零写权限**——不得录入、审批、修改任何单据；不得改账号与角色；不得改价格与库存；不得导出明细（仅汇总与脱敏导出）。
- **上游**：各业务部门数据；**下游**：经营决策（线下）。
- **产出**：不需考核；关注决策时效。
- **工作台**：即驾驶舱本身（营收/毛利/现金/在手订单/逾期应收/异常预警 6 张卡）。

## 5. 岗位 → 侧边栏菜单（名称数组 · 对齐 pm-server-openEuler 形式）

### 5.1 形式来源与三点调整

参考实现 `E:\my-pm\pm-server-openEuler\resources\views\layouts\app.blade.php:198-530`：顶部放全员共用入口，随后按角色分段（`<!-- 管理员菜单 -->`、项目经理、项目总经理、审核人、任务执行人、支援人员），每段用 `@if` 互斥，**通用协同项在每个角色段内重复出现**，管理员段只放管理类、不含业务操作。

v1.2 沿用该形式，做三点调整：① 把"哪一段属于哪个岗位"从 Blade 的 `@if` 搬进配置数组；② 菜单以**名称数组**呈现，角色显式绑定（`roles` ≥1）；③ 通用项**写进每个数组**并用校验强制，而不是靠"共用一段"隐式继承。

### 5.7 配置校验规则（`erp:guard:check` · M1~M6）

| 编号 | 规则 | 不通过的典型症状 |
|---|---|---|

| **L1 菜单守卫** | `config/navigation.php`（岗位→角色→名称数组）+ 名称→路由→权限映射 + 侧边栏 partial | 按数组逐项渲染并逐项 `can()`；**共享 11 项缺失即校验失败**；名称无映射则不渲染并记日志；配置缺失 → 空菜单（fail-closed） | 菜单项不出现（**不是灰显**） |
| **L2 路由守卫** | `routes/web.php` | 每条业务路由挂 `permission:`，且该权限必须 ∈ 页面主责/共享岗位权限集；`auth` 白名单仅限 P-105~P-111、P-131~P-133 | 403（自定义页） |
| **L3 数据守卫** | 查询作用域（Service/Repository） | 按 §3"数据范围"列过滤；列表、详情、导出、统计一致；**导出不得绕过** | 空列表 / 403 |

**L3 落地口径（实现回填，2026-11-07）**：§3 的"数据范围"是给人看的中文，执行层用 `positions.data_scope_type` 枚举承接——

| 枚举值 | 含义 | 查询行为 |
|---|---|---|
| `all` | 全部数据 | 不加条件 |
| `department` | 本部门 | `department_id = 本人部门`；**模型无 department 列时退化为 `self`** |
| `self` | 仅本人 | `owner 列 = 本人`（销售单 `salesperson_id`、采购单 `buyer_id`、检验单 `inspector_id`、项目 `creator_id`、图档 `uploader_id`、领料申请 `requested_by`） |
| `none` | 不看业务数据 | 一律 0 行（系统管理员，业务页面本身也已 403） |

多岗并集取**最宽**（all > department > self）；无岗位/未登录按 `self`（fail-closed）。无归属列的模型（如 `production_orders`、客户、供应商）**当前不过滤**，属已知边界，需补归属列或由"本线/本部门"关系表承接。
| **L4 动作守卫** | Blade 按钮 + 路由 | 按钮 `@can` 与路由权限同名同义；高危动作二次确认 + 审计（库存调整、价格变更、付款执行、删除、批量导入、薪资） | 按钮不出现；直提交 URL → 403 |

**必守的错配点**（现状就在犯，逐条改）：

1. `sales/order-show` 的确认订单、出货表单 → 加 `@can('sales.confirm')` / `@can('sales.ship')`；G1 上线后出货表单从销售页移除。
2. `production/order-show` 的领料、报工、完工表单 → 加 `@can('production.issue')` / `@can('production.report')` / `@can('production.complete')`。
3. 侧边栏 32 个无守卫菜单项 → 全部补映射并纳入 M4 校验。
4. `system` 分组拆成四个独立判断（`system.devops` / `system.user.view` / `system.role.view` / `admin.*.manage`）。
5. 会计页面（P-75~P-80）与出纳页面（P-142~P-146）**互不复用**，用不同权限不仅不同菜单、还必须不同路由。

### 8.2 403 与审计

- 新增 `resources/views/errors/403.blade.php`：文案「该页面不属于您的岗位（当前岗位：{岗位名}）」+「返回我的工作台」+ 页面所属岗位提示（**不暴露**其他岗位页面清单）。
- 401 仍走登录页；**403 不得重定向登录**（否则用户误判掉线）。
- 越权写入 `security_events`：`user_id, position_code, route_name, method, ip, ua, occurred_at`。
- 同一账号 5 分钟内越权 ≥3 次 → 高危标记，运维在"安全审计"页可见。
- 岗位 `status=0` → 登录后仅可访问个人资料，其余 403；账号 `status=0` → 登录直接拒绝。
- `system_admin` 访问任何业务路由 → 403 + 记录（这是"管理员不参与业务"的硬证据）。
- **老板驾驶舱**：`dashboard.view` 只授 `role_gm`，且该角色无任何写权限；驾驶舱内所有卡片与报表禁止出现明细单据操作按钮。

### 8.3 例外与边界

| 情形 | 规则 |
|---|---|
| 一人多岗 | 菜单取并集；权限按**页面主责岗位**判定；审计记录实际岗位 |
| 代理/顶岗 | 显式"代理授权"（有效期 + 授权人），不得直接改角色；带 `acting_for` 标记 |
| 老板只读（已启用） | 唯一入口是经营驾驶舱 + 报表中心（只读）；不得进任何业务操作页；导出只给汇总与脱敏 |
| 只读共享页 | 共享岗位仅获得"只读视图 + 明确列出的动作"，例如 FQC 在销售订单页只能看 |
| 运维临时排查 | 不允许"临时给业务权限"；只能查日志与账号，或走审批后**永久**调整岗位 |
| 兼容角色 | 仅可访问 §5.4 的共享页；不得因旧名获得 `sales.*` / `finance.*` 等业务权限 |

### 8.4 一致性自检（`php artisan erp:guard:check`，进 CI 门禁）

1. 每条 `routes/web.php` 路由都出现在页面表（白名单除外）→ 否则报"孤儿页面"。
2. 页面声明的 `permission` 都存在于 `PermissionSeeder` → 否则报"未定义权限"（可拦 `sales.confirm` 类 500）。
3. 岗位菜单项权限 ⊆ 该岗位角色权限 → 否则报"有入口无权限"。
4. 角色权限 ⊆ 菜单页面权限 ∪ 动作权限 → 否则报"有权限无入口"。
5. 所有 `route()` 名称可解析（`route:list` 通过）→ 拦 `.name(` 笔误。
6. 无"0 岗位引用"的孤儿权限（现有 33 条即此类）。
7. 每页唯一主责；共享岗位 ≤3（工程师族算 1 族）。
8. **M1~M6**（§5.7）全绿：角色非空、共享 11 项齐、无重名、映射完整、数量上限、页面归属唯一。
