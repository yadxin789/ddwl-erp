## 1. 范围与边界（先说明口径张力）

- P1-07 的 D-22 决策是"本期只做引导/设置/适配器骨架，订单拉取/重试/死信/对账移 P3-8"。本次正是执行 §4.4 第 8 项，不改 D-22 的历史结论，只把 P3-8 这一阶段补齐。
- 演示环境**没有淘宝/京东等真实平台凭证**，本轮**不连接真实平台**。适配器实现的是通用 REST 契约：
  - `GET {api_base_url}/orders` 拉单；
  - `POST {api_base_url}/shipments` 回写发货；
  - 未配置 `api_base_url` 时一律返回可读业务错误，不发起请求。
- 因此本轮验收的是**可测试的本地闭环骨架**：HTTP 拉单 → `ecom_orders/ecom_order_items` 落库 → 发货事件写 outbox → 回写成功/失败退避/死信 → 头行金额对账。真实淘宝 API 的签名、OAuth 刷新、退款/佣金结算不在本轮。

## 3. 数据与状态口径

- `ecom_orders.sync_status`：`pulled`（已拉取）/`shipped`（平台已发货待回写）/`pushed`（已回写平台）/`error`（回写失败）。
- outbox 状态：`pending` → `published`（成功）或 `failed`（等待下次重试）→ `dead`（第 5 次失败），`dead_at` 记录进入死信时间。
- 幂等键：`ecom_order_no` 唯一；同一单重复拉取只更新头字段并重建行项目，不重复建单；同一订单只保留一条未完成发货事件。
- SKU 映射顺序：`platform_sku_mappings(instance, platform_sku)` → 物料编码精确匹配；命中则 `sku_mapped=true` 并写 `material_id`，未命中保留原 SKU 供人工补映射。
- 对账：区间按 `ecom_orders.created_at`；头金额 = `total_amount` 合计，行金额 = Σ(`qty × price`)；单差 > 0.01 元或无订单行记为 mismatch。`paid_count` 含 `paid/shipped/completed`（已付款后的状态都算已支付），`shipped_count` 含 `shipped/completed`。
- 自动拉取：`manual` 只在页面/命令显式触发；`15m/hourly/daily` 由调度命令按 `last_synced_at` 判定。失败也会刷新 `last_synced_at`，避免每个 tick 反复打同一个不可用接口。

## 4. 测试与验收

`php artisan test --filter=EcomClosedLoopTest`：

1. `pull orders is idempotent and queues shipped shipment`：`Http::fake` 返回 2 单（1 待付款、1 已发货），首次新增 2、排队 1；二次拉取新增 0、更新 2、排队 0；`EL000003` 自动映射到物料。
2. `shipment push success marks order pushed`：outbox 回写成功 → `published`，订单 `sync_status=pushed` 且 `pushed_at` 有值。
3. `shipment failures retry until dead and can be reset`：接口持续 500，按退避推进 5 次 → `dead`、`retry_count=5`、订单 `error`；死信重置回 `pending` 且重试数清零。
4. `reconciliation flags header line mismatch and is idempotent`：两张单头 100/120、行 100/100 → 头 220、行 200、差异 1 单、`mismatch`；同周期重跑仍 1 条批次。
5. `ecom orders page renders closed loop sections`：`ecom-operator` 打开订单页可见"发货回写""订单对账"。

结果：`EcomClosedLoopTest` **5 passed / 40 assertions**。

## 6. 边界（本轮明确不做）

1. 不连接真实淘宝/京东；预置平台的真实签名、OAuth 刷新、接口域名、限流处理均未实现，只有通用 REST 适配器。
2. 拉取只做订单头/行；**不把电商单转成 ERP 销售订单**、不建客户、不扣库存、不生成出库单。
3. 发货回写由平台订单状态 `shipped` 触发；**不监听 ERP 出库/物流单**，运单号依赖平台回传或人工补录，ERP 不生成运单。
4. 对账只核"订单头 vs 订单行"，不是平台结算账单对账；不含退款、佣金、运费、优惠分摊、价税分离。
5. outbox 只支持 `ecom.shipment.push` 一种事件；通用事件分发、人工单条重试、批量补发未做。
6. SKU 映射只读 `platform_sku_mappings`，**没有维护界面**（P1-07 遗留仍在）；未映射行只保留原 SKU。
7. 自动拉取是"定时轮询 REST"，没有平台 Webhook/消息推送；`ackOrder` 仍为 false。
8. 金额按订单币种原值存储，不做多币种换算；对账无跨币种处理。
9. 演示店铺为离线数据（`custom:demo-shop`，无 `api_base_url`），不能作为真实接入验收。
10. 失败重试只在 `next_retry_at` 到期后处理；页面没有"立即重试失败项"按钮，只能等调度或死信重置。
