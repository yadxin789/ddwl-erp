## 2 数据字段（迁移 `000012` + `000013`）

| 列 | 类型 | 说明 |
|---|---|---|
| `priority` | string(10) | `low/normal/high`，默认 normal |
| `effective_date` | date nullable | 计划生效日；空则按批准日 |
| `scope_description` | string(500) nullable | 变更范围（工序/图档/装配段） |
| `impacted_material_ids` | json nullable | 受影响物料 id 列表；空表示整个 BOM |

## 3 影响分析（`App\Support\EcrImpactService`）

输入：BOM id + 受影响物料 id（空则取 BOM 所有行物料）。输出 JSON：

| 字段 | 口径 |
|---|---|
| `bom` | 编码/版本/产品编码/物料行数 |
| `materials` | 每个受影响物料的在手数量、成本价、库存金额（`inventory_stock.status=available` 求和，**绕过部门范围**看全公司） |
| `open_work_orders` | `production_orders.bom_id=该BOM` 且 `planned/released/in_progress` 的工单数、计划数、剩余数（计划−完工）、工单号 |
| `affected_sales_orders` | 上述工单关联的 `sales_order_id` 去重数 |
| `risk_level` | 有未完工工单或波及销售单 → `high`；仅有在库 → `medium`；否则 `low` |
| `risk_flags` | 人类可读提示（切换时点/旧料隔离/通知销售） |

**预览入口**：`GET /rnd/projects/{project}/ecr/impact?bom_id=` → `rnd.ecr.impact`，需要 `rnd.create` 且对该项目有 `manage` 权限；页面"预览影响"按钮用 fetch 渲染，不跳页。

## 4 表单与校验

`POST /rnd/projects/{project}/ecr`（权限不变：`rnd.create` + 项目 `manage`）：

- `bom_id` 必填且存在；
- `change_type` ∈ `bom/material/process/document`；
- `priority` ∈ `low/normal/high`（空默认 normal）；
- `effective_date` 可空，但填了必须 `>= 今天`；
- `title` ≤128、`reason` ≤1000、`scope_description` ≤500；
- `impacted_material_codes`：逗号分隔的物料编码，留空=整 BOM；未知编码直接报错，不静默丢；
- `replacement_material_codes`：逗号分隔；**有值时数量必须与受影响物料相同**，否则拒绝提交。

## 5 ECO 执行（`RndProjectService::approveEcr`）

审批链不变（`ecr.change` → 研发经理）。批准时同一事务内：

1. 复制旧 BOM 为下一版本（`V2`，编码加 `-V2` 后缀保证全库唯一），旧版 `superseded`；
2. 按 `impacted → replacement` 映射替换复制出的 BOM 行 `material_id`，`remark` 写"ECR 替代料：旧→新"；无映射的行原样复制；
3. 新 BOM 的 `effective_date` 取 ECR 计划生效日，未填用批准日；
4. ECR 写 `approved`、`approved_at`、`new_bom_id`、`eco_no`、`eco_executed_at`；
5. 幂等：已批准且已有 `new_bom_id` 直接返回，不重复生成 BOM/ECO。

## 9 未做 / 边界

- **只做"物料替换"一类 ECO 执行**：BOM 行新增/删除、用量修改、工艺路线变更、图档替换都只在 `scope_description` 里描述，ECO 不会自动改这些；需要时再扩 `change_lines_json`。
- **替代料必须一一对应**：不支持"一个旧料拆成两个新料"或"多个旧料并成一个"。
- **影响分析不扣预留**：在库只按 `available` 汇总，未扣已预留数量；也不计算成本差额（没有新料价格时无法算，避免拍脑袋）。
- **影响分析绕过行级范围**：研发看的是全公司影响面，因此库存/工单按 `withoutGlobalScopes()` 取数；这是评估口径，不是业务操作权限。
- **ECR 驳回原因未单独落字段**：走审批 `logs_json` 的备注；若要在变更单上直接展示驳回理由，后续加 `reject_reason`。
- **预览是实时计算，不是异步**：BOM 行数少时够用；BOM 行数很大时应改为队列任务。
