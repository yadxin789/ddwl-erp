# SoD 矩阵（职责分离）与回归基线（2026-11-09）

> 对应计划：`docs/整改完善计划-v1.4.md` P1-09（A 类制度化）
> 覆盖：29 个岗位 × 建（发起）/ 审（审批、确认）/ 执（执行）/ 改（修改主数据或单据）/ 导出
> 回归入口：`php artisan test --filter=SoDTest`（17 例），全量 `php artisan test`、`php artisan erp:guard:check`

## 1 口径与读法

1. **权限是唯一凭据**：表内写的是路由中间件实际要求的权限码（`permission:xxx`），不是"页面能看见"；按钮显隐只是 UI 提示，不作为授权依据。
2. **建**＝新建业务单据/主数据；**审**＝审批、确认、驳回（含代批）；**执**＝执行库存/资金/发货/检验等事实动作；**改**＝编辑主数据或他人单据（含主数据维护、模板维护）；**导出**＝导出文件/报表。
3. **"审 ≠ 建"**：同一岗位若同时出现在"建"和"审"，即为 SoD 硬冲突（自建自审），§3 逐条列出并已用测试锁死。
4. **数据范围是第二层**：即使持有权限，`HasDataScope` 仍按部门/归属列收窄可见行（P0-08），本矩阵不替代它。
5. **系统管理员不参与业务**：`role_sys_admin` 的 `data_scope=none`，对业务模型 0 行可见；其"改"列只涉及系统配置。
6. 兼容角色（`purchase_specialist`、`sales_specialist`、`warehouse_*`、`quality_supervisor` 等）计划于 **2026-12-31 停用**（P2-02/Q5），不在本矩阵 29 行内单列，但其权限仍与主角色取并集——所以主角色必须保持下列边界。

## 4 制度：新增岗位/权限必须补行

1. 任何新岗位（`NavigationRoleSeeder` 新增 `role_*`）必须在本文件 §2 增加一行，并在 §3 判断是否落入既有禁区；落入则必须新增至少 1 条 403 断言。
2. 任何新权限码必须写清所属动作列（建/审/执/改/导出）；**不得把"审"合并进"建"的权限**（P0-02 已把 `purchase.confirm` 从 `purchase.create` 拆出，后续同规则）。
3. `erp:guard:check` 的岗位/菜单/名称映射三项是硬门槛；本矩阵是"权限语义"层，二者都要过。
4. 兼容角色停用（2026-12-31）后重跑 §5，并把 §2 的并集说明删掉。
5. 每月或每次权限变更后执行：
   ```powershell
   & "C:\xampp\php\php.exe" artisan test --filter=SoDTest
   & "C:\xampp\php\php.exe" artisan erp:guard:check
   ```

## 6 已知未覆盖 / 待接线（如实记录）

1. **`quality.approve` 目前没有任何路由**：权限库里有，本次也补授给主岗 `role_qc_manager`（原来只有兼容角色 `quality_supervisor` 持有，主岗缺失属实际授权不一致），但检验结论的"审核/放行"仍只走 IQC 判定，没有第二人复核入口。SoD-09 只能断言角色边界，无法给出 HTTP 403 用例；需把"检验结论复核"接线后再补。
2. **审批越权返回 403 属本次改动**：`ApprovalController::decide` 对"申请人自批 / 非指定审批人"由 `302 + 错误提示` 改为 `403`。前端审批页对 403 没有专门提示（会落到通用错误页），后续可加友好页。
3. **服务层仍可绕过 HTTP 权限**：`ApprovalService::decide(..., $actorId)` 支持指定操作人（测试/系统内部用），它只校验"步骤审批人"，不校验 `permission:*`。业务代码不允许传 `$actorId`，但没有静态约束。
4. **盘点差异超阈值才审批**（§9.3 的 500 元阈值）；低于阈值 `auto_approved` 直通，这属于"授权范围内的自动执行"，不是 SoD 缺口，但矩阵没有单列阈值列。
5. **导出列全为"—"**：Q6 本期不做导出，已用测试断言"不存在 export 权限、不存在 `reports.export` 路由"，避免"有导出无范围"的假验收。
6. **29 岗之外的系统角色**（`role_task_auditor`、`role_task_executor`、`role_project_creator`、`role_support_staff`、兼容角色）未列入矩阵；它们不持业务单据权限，但**新增时必须补行**（§4 第 1 条）。
7. 矩阵按"权限码"归档，不按"页面 URL"；页面后续改路由名不影响矩阵，但改权限码必须同步本文件。

## 7 回滚

本项只新增文档与测试，另有一处控制器行为改动（审批越权 302→403）：

1. 删 `tests/Feature/SoDTest.php` 中 P1-09 新增的 4 个用例与文档；
2. `ApprovalController::decide` 去掉 403 分支、恢复 `back()->withErrors()`；
3. 重跑 `SoDTest` + 全量 + `guard:check`。
