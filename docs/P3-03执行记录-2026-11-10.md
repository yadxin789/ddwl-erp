# P3-03 执行记录：MFA/TOTP 二次验证（2026-11-10）

> 对应计划：`docs/整改完善计划-v1.4.md` §4.4 第 3 项"MFA/TOTP 二次验证（当前仅登录限流 5 次/分 + 失败记录）"。
> 结论：**已完成**。用户可自助开启 TOTP 二次验证；开启后每次登录必须先过 6 位动态码或一次性恢复码，未验证只能停留在验证页（可退出登录）。

## 1 实现方式

- **不引入第三方包**：`App\Support\TotpService` 按 RFC 6238 实现 HMAC-SHA1 / 6 位 / 30 秒，允许前后各 1 个时间窗（时钟偏差 ±30 秒）；自带 Base32 编解码。
- 用 RFC 6238 附录 B 向量做单元断言：`secret=12345678901234567890`、`T=59s` → 6 位码 `287082`，证明算法与标准认证器一致。
- 恢复码 8 个，格式 `XXXX-XXXX`，**只存 bcrypt 哈希**，用掉一个删一个。

## 2 数据字段（迁移 `2026_11_10_000015_add_mfa_fields_to_users.php`）

| 列 | 类型 | 说明 |
|---|---|---|
| `mfa_secret` | text nullable | Base32 密钥，模型 `encrypted` cast **加密落库** |
| `mfa_recovery_codes` | json nullable | 8 个恢复码的 bcrypt 哈希数组 |
| `mfa_enabled_at` | timestamp nullable | 开启时间；非空即要求二次验证 |
| `mfa_last_verified_at` | timestamp nullable | 最近一次验证成功时间 |

`User` 的 `fillable` 已补四列，`hidden` 增加 `mfa_secret`/`mfa_recovery_codes`，序列化不泄露。

## 3 路由与页面

| 方法 | 路径 | 名称 | 说明 |
|---|---|---|---|
| GET | `/mfa/setup` | `mfa.setup` | 未开启：展示密钥 + otpauth 链接 + 绑定表单；已开启：状态 + 恢复码（仅本次）+ 关闭表单 |
| POST | `/mfa/enable` | `mfa.enable` | 校验 6 位码后启用，生成 8 个恢复码（明文仅 flash 一次） |
| GET | `/mfa/verify` | `mfa.verify` | 登录后挑战页 |
| POST | `/mfa/verify` | `mfa.verify.submit` | 动态码或恢复码；失败 5 次锁 1 分钟 |
| POST | `/mfa/disable` | `mfa.disable` | 登录密码 + 当前动态码，双因子确认后关闭 |

入口：右上角用户菜单新增"账号安全 / 二次验证" → `mfa.setup`。没有新增权限点，任何登录用户只能管自己的 MFA。

## 4 拦截逻辑（`App\Http\Middleware\EnsureMfaVerified`）

- 挂在 `auth` 主路由组上（`routes/web.php` 第 66 行组）；
- 用户 `mfa_enabled_at` 为空 → 直接放行；
- 已开启且 session 里 `mfa_verified_at` + `mfa_user_id` 与当前用户一致 → 放行；
- 否则普通请求 302 到 `mfa.verify`，JSON 请求 423；
- **放行 `mfa.*` 和 `logout`**，避免被锁死在验证页无法退出；
- 登录成功时 `AuthController` 清掉 `mfa_verified_at/mfa_user_id/mfa_setup_secret`，保证每次新登录都重新验一次，不复用旧会话标记。

## 5 失败处理与告警

- 验证码错误：`RateLimiter` 按"用户 + IP"计数，5 次/1 分钟，超限提示稍后再试；
- 第 5 次失败写 `security_events`：`event_type=mfa_failed`、`level=high`、`detail=用户 xxx 二次验证连续失败`；
- 成功验证清空限流计数并更新 `mfa_last_verified_at`；
- 恢复码验证成功提示"已使用恢复码登录，该恢复码已作废"。

2. `test_enable_challenge_recovery_and_disable`：

## 8 边界 / 未做

- **默认选开，不强制**：没有"高权限岗位必须开启"的组织策略；管理员也不能强制/重置他人 MFA（避免运维接管账号）。
- **无管理员重置通道**：手机丢失且恢复码用完时，只能由 DBA 手工清 `users.mfa_*` 字段；这是有意的安全边界，需配套运维流程。
- **恢复码不能重新生成**：用完只能关闭再重开；没有"重新生成一批并作废旧码"的入口。
- **没有"信任此设备 N 天"**：每次登录都要验证；没有设备指纹/免验 cookie。
- **没有二维码渲染**：页面只给密钥和 otpauth 链接，不生成 QR 图片（避免引入前端二维码库/外部服务）。
- **限流在缓存层**：多节点部署时依赖共享 cache；单机 file cache 下每台机器各自计数。
- **未接入短信/邮件备用通道**，也未做 WebAuthn。
- **验证页沿用后台布局**：未验证用户仍能看到侧边菜单名称，但点任何业务页都会被拦回验证页；菜单本身不含数据。
