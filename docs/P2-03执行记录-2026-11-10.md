# P2-03 执行记录：权限颗粒度拆细（2026-11-10）

> 对应计划：`docs/整改完善计划-v1.4.md` P2-03（E-03）
> 结论：**已完成**。`quality.view` 拆为三页、`material.view` 拆为「页面 + 业务读取」，路由按页授权，种子/迁移/回滚齐备；guard 新增 **M8（一权限跨 >3 业务页告警）**；权限库 152 条、旧权限 0 条、菜单权限无孤儿。

## 1 拆分口径

| 旧权限 | 新权限 | 含义 | 路由 |
|---|---|---|---|
| `quality.view` | `quality.inspection.view` | 检验记录 / 待检任务 / 新建检验 | `quality.inspections`、`quality.pending`、`quality.inspections.create` |
| | `quality.template.view` | 检验模板页（只读） | `quality.templates` |
| | `quality.defect.view` | 缺陷代码页（只读） | `quality.defects` |
| `material.view` | `material.list` | 物料主数据列表页 | `materials.index` |
| | `material.read` | 业务模块读取物料数据（BOM/采购/生产/销售等引用） | 不单独设页，供业务读取校验引用 |

写入权限不动：`quality.operate` 仍管模板/检验/缺陷的 POST；`material.create/edit` 仍管新建/编辑。

## 2 代码改动

1. `routes/web.php`
   - `/materials` 的 middleware 由 `permission:material.view` → `permission:material.list`；
   - 质量页由一个大 group 拆成三个：`quality.inspection.view`（pending/inspections/create）、`quality.template.view`（templates）、`quality.defect.view`（defects）；POST 仍在 `quality.operate`。
2. `config/navigation.php` 菜单映射：
   - 物料主数据 → `['material.create','material.edit','material.list']`；物料查询 → `['material.list']`；
   - 检验记录/待检任务 → `quality.inspection.view`；检验模板 → `quality.template.view`；缺陷代码 → `quality.defect.view`。
3. `database/seeders/PermissionSeeder.php`：权限库新增 5 条、删掉 `quality.view`/`material.view` 两条。
4. `database/seeders/RoleSeeder.php`、`NavigationRoleSeeder.php`：原持有旧权限的角色改授新权限。按岗位细化：
   - 品质主管：三页全有；
   - IQC/IPQC/FQC：检验记录 + 缺陷代码（录缺陷要选代码），**不给检验模板**；
   - 生产主管/仓库主管/仓管/收货员：只给检验记录（来料/在制可见），不给模板和缺陷代码；
   - 其它原 `material.view` 角色：`material.list + material.read`（保持页面可用与业务引用都不丢）。
5. 新增迁移 `database/migrations/2026_11_10_000010_split_view_permissions.php`（已 migrate DONE）：
   - 先给持有旧权限的角色补授等价新权限（保留 `role_has_permissions` 原关系），再删旧权限与旧授权；
   - `down()` 反向：恢复旧权限并回授，删新权限；
   - 在 `migrate:fresh` 场景下权限表为空，只创建新权限，随后 seeder 正常授权。
6. `app/Console/Commands/GuardCheck.php` 新增 **M8**：统计每个权限在菜单映射里覆盖的**去重路由数**，>3 打印告警（不阻断，符合计划"告警"口径）。

- guard 输出：`岗位/兼容角色 33、共享菜单 11、名称映射 122、权限库 152、M1~M7 全部通过`；

## 5 未做 / 边界

- **`material.read` 目前只做权限声明，没有在业务读取接口上逐个加校验**：业务模块（BOM、采购、生产、销售）取物料数据走的是模型查询，不是 `materials.index` 页面；本期只保证"页面权限"与"读数据权限"分开，未给每个 service 加 `can('material.read')`。要彻底闭环需在 P3 给服务层补授权切面。
- **`quality.template.view` 只授品质主管，检验员看模板会被 403**：按职责分离口径（模板维护属主管），若客户要求检验员也能只读模板，改 `NavigationRoleSeeder` 一行即可。
- **`quality.view`/`material.view` 已物理删除**（权限表与角色授权），不是"保留别名"。外部若有脚本/报表引用旧名会失效；本期无导出，风险面在自定义脚本。
- **M8 只统计 `menu_items` 映射**，不统计仅出现在路由 middleware 但没进菜单的权限；`hr.operate` 是当前唯一超阈值项，未在本期拆。
- **7 个待退场旧角色仍持有旧权限的超集**（P2-02 的 12/31 才摘除）：它们不在本次拆分授权对象里，旧角色上的 `quality.view` 已被迁移删掉并补新权限，行为不丢。
- 权限数变化（149 → 152）会让任何硬编码"149"的文档/断言过期；已在 guard 输出与本文档更新，测试未硬编码数量。
