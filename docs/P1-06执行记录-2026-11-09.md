## 1 一句话结论

IQC 有了独立待检台：直接按 **`qc_hold` 库存批次** 列物料/批次/供应商/到货日/数量，条数与库存批次数一一对应；IQC 判定后每行落一条检验记录并绑定收货单（`ref_type=goods_receipt`、`ref_id=收货单ID`），可按收货单反查；检验阶段按岗位锁死，IQC 提交 IPQC 直接 **422**。

## 3 规则表

### 3.1 待检台口径

| 项 | 规则 |
|---|---|
| 数据源 | `inventory_stock.status='qc_hold'` 且 `qty>0` 的批次行（不看单据状态，避免"库存已转走但单据还挂 pending_qc"的假待检） |
| 排序 | 到货日 → 物料 |
| 供应商 | 按 `material_id + lot_no` 反查最近一张 `goods_receipt_lines`，再取收货单 `supplier_id` |
| 条数断言 | 页面显示 `qc_hold 批次 N 条`，`N = select count(*) from inventory_stock where status='qc_hold' and qty>0` |
| 只读 | 页面不做判定，判定入口跳收货单详情（避免两套判定路径） |

### 3.2 岗位锁阶段

| 岗位 | 锁定阶段 | 说明 |
|---|---|---|
| `iqc-inspector`（`role_qc_iqc`） | IQC | 只能录 IQC；提交 IPQC/FQC/OQC → 422 |
| `ipqc-inspector`（`role_qc_ipqc`） | IPQC | 只能录 IPQC |
| `fqc-inspector`（`role_qc_fqc`） | FQC | 只能录 FQC |
| `quality`（`role_qc_manager`） | 不锁 | 全阶段可录（复核/代录），页面显示"品质主管视角" |

锁定经 `QualityService::stageForUser()` 读 Spatie 角色判定，**不信表单**；控制器再次比对 `$data['stage']` 与锁定值，不一致 `abort(422)`（Web 与 JSON 都是 422）。

### 3.3 检验记录绑定

| 字段 | 值 |
|---|---|
| `stage` | `IQC` |
| `material_id` | 收货行物料 |
| `ref_type` / `ref_id` | `goods_receipt` / 收货单 ID |
| `sample_qty` | 该行收货数量 |
| `qualified_qty` / `defect_qty` | 判定填写的合格 / 不合格数量 |
| `result` | `defect_qty=0 → accepted`，否则 `rejected` |
| `inspector_id` / `inspected_at` | 当前 IQC 用户 / 判定时刻 |
| `remark` | `收货单 {receipt_no} 批次 {lot_no}` |
| `record_no` | `NumberGenerator::generate('inspection')` |

## 4 本轮抓到的两个真 bug

1. **IQC 打开收货单 404**：`receiptShow` / `inspect` 用路由模型绑定 `GoodsReceipt`，该模型带 P0-08 行级范围（收货单归属仓库部门），IQC 属品质部 → 绑定阶段直接 404，P0-01 刚归位的"IQC 能判定"在页面上仍然走不通。改为 `int $receipt` + `withoutGlobalScopes()->findOrFail()`，授权留在 `permission:purchase.view` / `quality.receipt.inspect`。
2. **IQC 判定末尾炸 `checkPoCompletion(null)`**：`$receipt->purchaseOrder` 关系走 `PurchaseOrder` 的采购行级范围（buyer 维度），IQC 看不到 → 关系返回 null → 类型错误 500。改为 `PurchaseOrder::withoutGlobalScopes()->with('lines')->find(po_id)`，无 PO（直接收货场景）跳过完成度检查。

两条都是"测试里用业务角色真实提交"才暴露的，和 P1-04 那几个 scope bug 同一类。

## 6 未做 / 边界

- **只做 IQC 待检**：IPQC/FQC 没有独立待检台（计划只要求 qc_hold 收货批次），制程/成品待检仍靠检验记录页 + 手工录入；IPQC/FQC 阶段锁定已生效，但"待检工单/待出货批次"没做列表。
- **供应商靠 `material_id + lot_no` 反查**：同一物料同批次号跨供应商时会取最近一张收货单，可能张冠李戴；根治要给 `inventory_stock` 增 `receipt_id` 列（本轮不动表）。
- 待检台**不做判定**，判定仍在收货单详情（避免两套入口）；页面上"判定"按钮对非 IQC 岗位也显示，但点进去提交会被 403。
- `inspection_records` 仍是"一行收货行一条记录"，未做抽样明细（多个检测项/缺陷代码级记录）。
- OQC 阶段没有岗位锁（演示账号无 OQC 检验员），主管可录。
- 待检台分页未做（一次全量列出 `qc_hold`，演示数据量级可接受；上量后按 20/页分页）。
