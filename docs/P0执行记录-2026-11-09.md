## 5. P0-04 库存调整两段化 + 500 元阈值（D-16 / 计划 §9.3）

原实现的问题：`InventoryController::adjustmentStore` 直接改库存并写流水（**无审批、无单据、无金额口径**），
盘点差异 `ProductionOrderService::adjustStocktake` 同样直接改库存；谁有 `inventory.adjust` 谁就能改账，等于仓管自批自改。

| 项 | 改动 |
|---|---|
| 新表 | `database/migrations/2026_11_09_000001_create_inventory_adjustments_table.php`：单号、来源（manual/stocktake）、关联库存行/盘点行、状态（pending/approved/auto_approved/void）、调整前/后/差异数量、单位成本、金额、阈值、`auto_approved`、发起人/审批人/时间/审批意见 |
| 模型 | `app/Models/Inventory/InventoryAdjustment.php`（关系 material/warehouse/requester/approver + `scopePending`） |
| 参数 | `config/erp.php → inventory.adjust_approval_threshold`（默认 500，可用 `ERP_INVENTORY_ADJUST_THRESHOLD` 覆盖） |
| 服务 | `app/Services/InventoryAdjustmentService.php`：`unitCost()`（物料标准价占位 `cost_price` → 最近采购单价 → **null 强制审批**）、`requestManual()`、`requestStocktakeLine()`、`approve()`（幂等）、`reject()`、`apply()`（唯一改库存入口，流水 `ref_type=adjustment`、`ref_id=调整单 id`） |
| 生产侧 | `ProductionOrderService::adjustStocktake` 改为**每条差异生成调整单**；全部差异都自动通过才把盘点单置 `adjusted`，否则留待审批，审批通过后由 `syncStocktakeStatus()` 收口 |
| 权限 | 新增 `inventory.adjust.request`（发起：仓管 / 仓库主管 / 生产组长）、`inventory.adjust.approve`（审批：仅仓库主管）；权限库 139 → **141** |
| 路由 | `POST /production/stocktakes/{st}/adjust`、`POST /inventory/adjustments` → `permission:inventory.adjust.request`；`POST /inventory/adjustments/{id}/approve|reject` → `permission:inventory.adjust.approve`；列表页允许三种权限任一进入 |
| 页面 | `resources/views/inventory/adjustments.blade.php` 重写：新建表单（阈值提示 + 预留量保护）、待审批表（`@can('inventory.adjust.approve')` 才出现通过/驳回按钮）、调整记录（自动通过/已审批/已驳回三态） |

阈值口径（按 §9.3）：
- 金额 = `|差异数量| × 单位成本`；**单位成本取不到时金额记为 null，一律强制审批**（不让"算不出来"变成"免审"）。
- `金额 < 500`：当场生效，单据状态 `auto_approved`、`auto_approved=true`，审批意见写"低于阈值 X 元，自动通过"。
- `金额 ≥ 500`（**含等于**）：单据 `pending`，**库存不动**，等仓库主管审批；驳回 → `void`，库存同样不动。
- 数量对齐到 2 位小数（`inventory_stock.qty` 是 `decimal(18,2)`，避免单据与实际库存差尾数）。

## 9. P0-08 数据范围兜底 + 归属列 + 报表口径（C-01 / C-02 / C-03）

原实现的问题：① `HasDataScope` 找不到归属列时**静默放行全表**（缺列 = 无隔离）；② 工单/客户/供应商/收货/发票/账单六张表**根本没有归属列**，行级范围形同空转；
③ 库存没有按仓隔离，仓管能看全部仓库；④ 报表四张页面的分子分母范围不一致（订单带 scope、发票不带），且 `report.view` 一个权限同时开四张报表给品质/采购/销售/行政/研发/总经理等一众岗位。

| 项 | 改动 |
|---|---|
| 兜底语义 | `HasDataScope` 改为**默认 fail-closed**：声明了范围（self/department）却找不到可用归属列 → `whereRaw('1=0')`；公共主数据可用 `$dataScopeUnscoped = true` 显式豁免（当前无模型使用，已在文档登记这一约定）。归属列统一 `qualifyColumn()`，避免 join 时报 `Column 'owner_id' in where clause is ambiguous` |
| 库存按仓 | 新增 `$dataScopeWarehouseColumn`：无人员归属列时按"**本部门仓**"过滤（`warehouses.department_id` 归属本人的部门），无部门/部门无仓 → 0 行 |
| 迁移 | `2026_11_09_000002_add_data_scope_columns`：`production_orders(department_id,created_by)`、`customers(owner_id,department_id)`、`suppliers(owner_id,department_id)`、`goods_receipts(receiver_id,department_id)`、`customer_invoices(owner_id,salesperson_id)`、`supplier_bills(owner_id,buyer_id)`、`warehouses(department_id)`；并按岗位把演示库历史数据回填到对应部门/责任人（工单→生产部/生产主管、客户→销售部/销售专员、供应商→采购部/采购专员、收货单→仓储部/收货员、仓库→仓储部） |
| 模型 | `ProductionOrder` / `Customer` / `Supplier` / `GoodsReceipt` / `CustomerInvoice` / `SupplierBill` 接入 `HasDataScope` 并声明列；`InventoryStock` 走仓储列；`SalesOrderLine` 补 `order()` 关系供报表用 `whereHas('order')` |

| 角色 | 品质主管→quality、采购主管/采购专员→supplier、销售主管/销售专员→sales、会计→finance、总经理→四条全给；研发经理/仓库主管/行政经理**收回**报表权限（原先只是"顺手给了 report.view"） |
| 顺带修 | 兼容角色 `warehouse_keeper` / `warehouse_supervisor` 收回 `sales.view`（只保留 `sales.ship` 走发货台）；`system_admin` 从"全部权限"收窄为 `system.*` / `admin.*` / `ai.*`（系统管理员是 none 范围，授权与数据范围必须一致）——这两条是审计"兼容角色放大授权"的即时止血，P2-02 仍按 2026-12-31 整体停用 |

### 10.1 测试写法上的一个坑（已记录，后续 P0/P1 测试沿用）

写"无权限应 403"的 HTTP 断言时，如果目标对象在演示库里不存在（采购单/收货单均为 0 行），
**路由模型绑定先于权限中间件执行**，会先返回 404 而不是 403，断言 403 必失败。
因此本轮改为"路由中间件栈断言 + 角色权限断言"（`SoDTest`），需要真实对象才能断 403 的用例，
必须先在测试里造单据并回滚——`InventoryAdjustTest` 走的就是这条路径（事务内造 pending 单据，再让仓管 POST 审批得 403）。

### 10.2 顺手修掉的基线噪音（属计划 P2-01，但阻断"全绿"）

- 删除 `tests/tests/` 重复测试目录（审计报告 E-01）。
- `tests/Feature/ExampleTest.php` 原断言"未登录访问 `/` 得 200"，实际应为 302 跳登录，改为断言重定向到 `login`。

### 10.3 P0-04 踩到的两个具体坑（避免复发）

1. **反推数量差别用 `max($unit, 0.01)` 兜底**：演示库存在 `cost_price=0.0035` 的物料，把单价截断成 0.01 会把"600 元场景"算成 210 元、
   被自动通过，看起来像阈值逻辑写错。反推必须用真实单价。
2. **`inventory_stock.qty` 是 `decimal(18,2)`**：调整后数量按 4 位小数写入时，单据 `after_qty` 与库存行会差尾数，断言必失败；
   现在 `requestManual` / `requestStocktakeLine` 入口统一 `round(...,2)`。

### 10.4 测试里"假游客"的坑

`setUp` 里为了造数据用了 `actingAs()`，之后的"未登录应 302"用例仍带着登录态，断言会拿到 200。
必须显式 `Auth::logout()` + `$this->app['auth']->forgetGuards()` 再断言（`FileDownloadTest` 已这么写）。
