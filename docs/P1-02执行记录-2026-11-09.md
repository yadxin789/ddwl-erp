## 1 一句话结论

标准成本按"版本"落地：同一物料同一时点只有 1 个 active，改价只能新建版本；出货按**发货时点**版本结转 `sales_order_lines.std_cost_amount`，采购收货按"实际单价 − 标准成本 × 数量"把**价差单列**写进库存流水，不摊入单笔销售成本。演示环境由 `DemoStandardCostSeeder` 给 A 类物料写虚拟标准价（`source=demo`，页面标"演示数据"），上线后由客户财务在维护页自助改价。业务角色访问该页 403。

## 3 规则落地（与 §9.4 对齐）

| 规则 | 实现位置 | 说明 |
|---|---|---|
| 同一时点仅 1 个 active | `StandardCostService::setVersion()` | 新建版本时旧 active 自动置 `superseded` 且 `effective_to = 新生效日前一天`；同生效日同来源重复提交抛 `DomainException` |
| 禁止覆盖历史 | 同上 | 没有"修改单价"入口，只有"新建版本 / 停用版本" |
| 旧单据按发生时点版本 | `effectiveAt()` 查询 `status IN (active,superseded)` + 生效区间 | 必须包含 superseded，否则历史日期回查为空（本轮测试抓到并修正） |
| 发货结转 | `SalesOrderService::ship()` | 每行在 FIFO 循环前取一次发货时点单价，`issue()` 写入 `std_cost`，循环后累加 `std_cost_amount`（分批出货按各批次时点版本累加） |
| 采购价差 | `PurchaseOrderService::receive()` → `InventoryService::receipt()` | 实际单价取采购订单行 `unit_price`，`price_variance = (actual − std) × qty`，只入库存流水 |
| 无标准兜底 | `costAt(..., allowFallback=true)` | 先取最近采购价（只看已确认及以后状态的 PO），再取 `materials.cost_price`；生成 `source=fallback` 版本并在页面标黄；`cost.block_ship_without_standard=true` 时抛异常阻断 |
| 收货不得造版本 | `receive()` 调 `costAt(..., false)` | 收货不污染标准成本版本表；无版本时价差为空 |
| 期初演示价 | `DemoStandardCostSeeder` | A 类口径＝按"在手数量 × 现价"累计覆盖 70% 库存价值；虚拟价取 `cost_price>1` → 否则最近采购价 → 否则 10.00 元；写 `source=demo`、`effective_from=2026-01-01` |
| 维护入口权限 | `PermissionSeeder` + `NavigationRoleSeeder` | 会计得 `cost.standard.manage/view`，总经理得 `cost.standard.view`；销售/生产/仓管等业务角色无权限（403） |
| 菜单 | `config/navigation.php` | 会计菜单加"标准成本维护 / 成本差异分析"，总经理菜单加"成本差异分析"；两菜单项均指向**无参路由**（M7 通过） |
| 工作台两列 | `config/dashboard.php` + `DashboardService` | 会计/总经理工作台新增"本月毛利（标准成本）""本月采购价差"，点击跳差异分析页 |

- `GET /finance/standard-costs`（`finance.standard-costs`，`cost.standard.manage`）：物料列表 + 当前 active 版本 + 版本号/来源 + 生效日 + 新建版本 + 停用；页头给"演示价 N 条 / 临时兜底 N 条 / 未定标 N 个"。
- `POST /finance/standard-costs`（`finance.standard-costs.store`）：新建版本。
- `POST /finance/standard-costs/deactivate`（`finance.standard-costs.deactivate`）：停用 active 版本。
- `GET /finance/cost-variance`（`finance.cost-variance`，`cost.standard.view`）：期间可选；
  - 采购价差合计 + 毛利合计；
  - 价差按物料、价差按供应商（流水 → 收货单 → 采购单 → 供应商）；
  - 毛利（标准成本口径 = 出货收入 − 标准成本结转）按物料；
  - 量差（BOM 标准用量 × 计划数量 vs 实际领料）。
- 视图：`resources/views/finance/standard-costs.blade.php`、`finance/cost-variance.blade.php`。

## 5 顺带修的两个真问题（都是本轮测试暴露的）

1. **服务层被行级数据范围挡住**：`InventoryService::lockStock()` 与 `SalesOrderService::ship()` 查 `InventoryStock` 时受"本部门仓"全局 scope 过滤，销售账号出货会查不到库存（报"库存不足"）；`PurchaseOrderService::receive()` 用 `PurchaseOrder::findOrFail()` 时仓管收货会被 `buyer_id` 归属过滤成 404。已改为服务层 `withoutGlobalScopes()`（授权仍在路由/Permission 层），并在代码注释里写清原因。
2. **新列没进 `$fillable` 被静默丢弃**：`inventory_transactions` 的 `std_cost/actual_cost/price_variance` 与 `sales_order_lines.std_cost_amount` 未加入模型 `$fillable` 时，写入全部为 null，测试直接断言落库值才暴露。已补齐 fillable + casts（沿用经验笔记 `laravel-feature-test-empty-form-hides-real-write-path`）。

## 7 未做 / 边界（如实记录）

- **变更审批**：维护页目前"财务建版本即生效（`approved_by` 记当前人）"，未接 P1-01 审批流的"改价需审批"。计划原文写"新建版本（走审批）"，本轮按演示可跑通的口径先落"会计直接生效 + 留痕"，接审批流留 P1-03 一并做（会涉及审批类型与影响预览）。
- **影响预览**（"哪些在途订单会受影响"）未做：需要"未发货订单行 × 当前版本"的差异面板，本轮只在页面文案提示"改价不追溯已发货单据"。
- **量差**：按 `BOM qty_per × 计划数量` 对比实际领料，未计 `loss_rate`（损耗率）与替代料；演示库 BOM 数据少，该区块多数为空。
- **价差按供应商**依赖 `goods_receipts → purchase_orders → suppliers` 关联，手工调整的入库（无收货单）不会归集到供应商。
- **毛利按订单日期**归期（不是按发货日期/开票日期），因为演示库发票数据为 0；P1-03 做核销闭环后应改为"开票净额"口径。
- 未改动 `materials.cost_price` 语义（仍作兜底价），财务正式定标走版本表。
- 计划 §9.4 的"变更审批"与"影响预览"两项，属于本行验收未硬性要求的剩余工作，已在此记录，不当作已完成。
